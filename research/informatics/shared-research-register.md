# Shared research register — M1–M48

The same compact research entry appears in each native modulus record, following
the existing M9P24 pattern in Alpha, Beta, Gamma, Epsilon, the combined Fibonacci
view, Other Geometry and Geometry Summary. The register and First Principles
Genomics retain their lightboxes. The register contains fourteen unique primary
publications; E03, E06, E08 and E11 are the four HERO selections within that set.

The collection is shared background for the initial OXTR research programme.
Modulus relevance awaits assessment. The existing open questions retain their
explicit M9/P24 reference. No per-modulus biological questions or WSS scores are
generated by this extension. Publication trust remains the existing provisional
editorial appraisal, with its review depth, methods, limitations and citation date.

## Source and exports

`research-register.json` in this directory is the canonical literature source.
The sync script generates the browser publication data and attaches the same
register to the public data. Stable E01–E14 identifiers and DOIs identify papers.
`hero_publication_ids` references the four members of that collection.

- `Informatics/pilot-v1/research-register.json`: complete standalone bibliography,
  scope, hypothesis reference, appraisal rubric, findings and limitations.
- `dataset.json`: complete bibliography once at `research_register`; each record
  identifies its shared reading under `research.background_literature`.
- `m1.json` through `m48.json`: each includes the complete `research_register`,
  allowing a consumer to interpret a single downloaded file independently.
- `records.csv`: register version and publication IDs alongside existing data.
- `research_publications.csv`: one row per study.
- `m1-m48-data.zip`: matching dataset, register and CSV exports.

Schema 2.2.0 adds literature metadata. Mathematical observations, native and reduced
sequences, geometry, verification records and research tiers remain unchanged.
Every tier retains a null WSS score and empty assessed-evidence list. Shared reading
uses `relationship: background_context`, outside the tier evidence fields.

After generating mathematical data, regenerate literature and exports together:

```sh
python3 research/informatics/pilot/sync_research_register.py --data-dir Informatics/pilot-v1 --browser-js Informatics/science-studies.js
python3 research/informatics/pilot/sync_probability.py --data-dir Informatics/pilot-v1
INFORMATICS_DATA_DIR=Informatics/pilot-v1 python3 research/informatics/pilot/export_csv.py
python3 tools/check-informatics-register.py
```

The local Informatics working directory mirrors the source under
`research/research-register.json` and the data under `data/m1-m48-v1`. Its copied
sync script accepts `--source research/research-register.json` explicitly.

## Notion alignment

Reuse the existing **Universal Informatics — Peer-reviewed Evidence** source.
The existing **Research Atlas** database now includes two linked view tabs:
**Research register** (14 studies) and **HERO studies** (the filtered four).
The five pre-existing Atlas views remain intact.

Each publication has a `Background for Atlas` relation to all 48 records; the
reciprocal field is `Background literature`. Each Atlas record also has a compact
register link, register version and current JSON link. The separate assessment
relations remain untouched. All 144 WSS assessment rows retain their original
unassessed state.

`notion-research-register.json` records the existing collection, view and page IDs
for future upserts. Match publications by Study ID and DOI, then update the same
pages. Preserve unrelated properties and the assessment relations. The Notion
pages include the same findings, limitations, methods, appraisal rationale,
score components and dated citations as the canonical JSON. Jadad is recorded
as not applicable, with no numeric score.

This release aligns version 2026-10-17.1 across the three representations. It does
not establish automatic Notion-to-website publishing. Future edits require the
same coordinated export, Notion update, readback and staging proof workflow.
